# 模型训练配方（参考）

> 本仓库不含模型权重。微调模型是让管线"有断语能力"的关键一环——配方公开，
> 数据与知识层由使用者自备。确定性 QA（四化锚点/大限映射/流年映射/三元绑定）
> 可直接用排盘引擎逐盘程序化导出，参考 tools/prompt_builder.py 的权威表输出口径。

## 为什么需要微调，而不是纯 prompt

实测经验：长 prompt（排盘事实表 + 权威表 + 规则判定 ≈ 万级 token）下，
通用模型在**确定性映射**上不稳定：

- 大限四化照抄生年 / 干支错位（三单三错）
- 大限宫位换算约半错（需"宫名→宫干→四化表→落宫"多步心算）
- 自化标签：引擎无自化也会编

通用模型 + 强提示可以解决"读表照抄"，但解决不了"多步心算"。
解法两条腿：

1. **工程侧**：能查表的全部注入权威表（本仓库做法）——引擎有 `daxianPalaceMap`
   144 条、`liunianPalaceMap` 1440 条显式映射，禁止模型心算。
2. **模型侧**：微调把常见映射与口诀内化进权重，减少对 prompt 长度的依赖。

## 推荐基座与量化

| 项 | 值 | 理由 |
|---|---|---|
| 基座 | Qwen3 类 27B（或同档开源） | 中英双语强、上下文 256K 级 |
| 量化 | Q6_K GGUF（约 22GB） | 32GB 显存可跑；Q4 质量损失明显 |
| 推理框架 | llama.cpp / Ollama | 单卡 Vulkan/CUDA 均可 |
| 速度 | 27B Q6_K 单卡约 13-14 tok/s | 一次全量分析 5-10 分钟可接受 |

## 训练数据构成（程序化为主）

确定性数据**不要靠 LLM 生成**（会带回同样漂移）。推荐程序化构造：

| 数据集 | 规模建议 | 内容 | 生成方式 |
|---|---|---|---|
| 四化锚点 QA | 500-800（豁免去重） | "丙年四化是什么" → 天同禄/天机权/文昌科/廉贞忌 | 表驱动，零幻觉 |
| 大限映射复述 | 5000+ | "36-45岁大限命宫在田宅" → 宫名/干支/四化全复述 | 引擎逐盘导出 |
| 流年映射 | 5000+ | "2026丙午年流年命宫落夫妻" | 引擎逐盘导出 |
| 三元绑定 | 数千 | "天同禄在疾厄（丙干）" 星曜-四化-落宫绑定 | 引擎逐盘导出 |
| 断语 SOP（自备知识） | 数千 | 按自有知识库出 QA（人审） | 知识层自备 |

铁律：

- **去重豁免口诀锚点**——通用去重会把"同一口诀的翻版问法"全删光，导致模型口诀记忆归零。
- **清洗 CoT**——若基座自带思考链，训练样本里的推理过程会污染输出格式。
- **错误样本做 DPO 对**——把已知漂移形态（照抄生年当大限四化等）做成负例，训练"不要这样"。

## 训练（以 QLoRA 为例）

```bash
# 4bit QLoRA，2 epoch，约 58h @ V100 32GB（规模参考）
python -m axolotl.cli.train config.yml
# 合并 LoRA → 转 GGUF → Q6_K
python convert_hf_to_gguf.py merged/ --outfile ziwei-v6.gguf --outtype q6_k
```

## 部署

```bash
ollama create ziwei-v6 -f Modelfile   # FROM ./ziwei-v6.gguf
# num_ctx 必须 ≥32768——prompt 注入量大，2048 默认值会静默截断出英文思维片
```

接入管线：把 `prompt_builder.build_prompt()` 输出发给模型 → 成品走
`reconcile_gate.verify()` → 过闸进六件套。

## 升级验证（每个新版本必须做）

1. **金标准盘回归**：同一批测试生辰，对比上一版全部结构字段（宫位/四化/岁段），零硬错。
2. **同盘跨单一致性**：同一张盘问两次/拆两单，同一星曜的落宫断语必须一致。
3. **多步心算专项**：大限四化 / 大限宫位 / 流年命宫三项单独出题，逐条对引擎。
4. 上述任何一项漂移即拦退，禁止带病上线。
